## Проверка 23 сентября (ветка `fix/handoff-prep`)

Chromium (headless, сборка Playwright 1194) через локальный HTTP-сервер. Это
отрисовка настоящим браузерным движком с заданными размерами viewport — **не
физические устройства и не эмуляция сенсорного ввода**. Safari и Firefox не
запускались.

Размеры: 320×568, 390×844, 430×932, 768×1024, 1024×600 (горизонтальная
ориентация), 1440×900.

Геометрия на всех шести размерах:

- `scrollWidth === clientWidth` — горизонтального скролла страницы нет;
- все пять секций (`how`, `examples`, `pricing`, `request`, `faq`) присутствуют;
- глобальный `overflow-x: hidden` не добавлялся; за границы выходит только
  декоративная сцена hero, которую обрезает сам блок, и лента миниатюр с
  собственной прокруткой;
- значения до и после правок 23 сентября совпали — регрессий вёрстки нет.

Сценарии (390×844, если не указано иное):

- мобильное меню: открытие, `aria-expanded`, Escape закрывает и возвращает фокус
  на кнопку, все пять разделов в меню;
- «Примеры»: пять вкладок переключают заголовок, обложку и винил; винил
  подгружается и отрисовывается (natural 800 px, отрисовка 251–341 px);
- FAQ: шесть пунктов, раскрытие мышью и клавиатурой;
- «Цены» → «Заказать песню»: пакет действительно выбирается в форме
  (`product = song`), страница прокручивается к заявке;
- форма: пустая отправка даёт конкретную ошибку по полю («Выберите, для кого песня.»);
- **D01:** форма заполнена → клик по «политике обработки персональных данных» →
  документ открывается в новой вкладке, исходная остаётся на `/`, контакт и имя
  на месте. До правки тот же сценарий терял значение поля контакта;
- кнопка паузы анимации помещается в viewport на 1440 (right = 1424 при vw = 1440);
- ошибок JavaScript и сетевых ответов ≥ 400 в консоли нет. Запросы к Google Fonts
  блокирует сетевая политика среды проверки — это ограничение песочницы, не сайта.

Производительность изображений: переключение четырёх вкладок «Примеров»
догружает 137 КБ вместо ~5 МБ до правки. Суммарный вес изображений 968 КБ.

Автоматические проверки: `npm ci --ignore-scripts`, `npm run check` — без
ошибок, `npm test` — **31/31** (было 29, добавлены два регрессионных теста на D01).

**Не проверено 23 сентября:** физические iPhone/Android, Safari, Firefox,
экранная клавиатура, screen reader, системная настройка reduced-motion, 200 %
text zoom, Lighthouse / Core Web Vitals, медленная сеть. Настоящее аудио и
серверный приём заявок отсутствуют в проекте, поэтому не проверялись.

## Реальный браузер

Встроенный браузер Codex, локальный HTTP-сервер. Это отрисовка настоящим браузером с заданными размерами viewport, а не jsdom и не физические телефоны. Версия движка интерфейсом проверки не предоставлена. Safari и Firefox отдельно не запускались.

Проверка геометрии выполнена на 17 размерах:

| Категория | Viewport, px |
| --- | --- |
| Узкие телефоны | 320×568, 360×740 |
| Телефоны | 375×812, 390×844, 414×896, 430×932 |
| Промежуточные | 520×740, 600×800, 601×800, 859×900, 860×900 |
| Планшеты | 768×1024, 1024×768 |
| Desktop | 1366×768, 1440×900 |
| Низкие / landscape | 844×390, 1024×600 |

Общего горизонтального скролла нет. В браузере с обычным scrollbar ширина содержимого на 15 px меньше viewport — проверки сравнивали scrollWidth с clientWidth. Локальный скролл миниатюр допускается. Глобальное overflow-x:hidden не добавлено; удалено лишнее обрезание содержательных разделов FAQ/формы. Hero обрезает только декоративную сцену.

Скриншоты просмотрены для desktop 1440×900, tablet 768×1024, mobile 390×844 / 320×568 и landscape 844×390. Отдельно просмотрены исходные Hero v2 и «Как рождается ваша песня» из Claude Design. Проверены композиция, облака, типографика, обложки, переходы секций, открытое меню, FAQ, ошибка, выбранный тариф, подготовленная заявка и юридические страницы.

## Сценарии

- Мобильное меню: открытие/закрытие, Escape и возврат фокуса, переходы к разделам. Подложка не становится прозрачной при открытии. Все разделы доступны.
- Desktop-навигация, якоря, CTA и отсутствие двойного отступа от шапки.
- Hero: пауза, читаемый заголовок, уменьшенный путь прокрутки, статичный режим при низком окне. Управление исчезает вместе со сценой и не удерживает невидимый фокус.
- Примеры: все пять вкладок, Arrow/Home/End в логике и End в браузере; смена заголовка, обложки и описания; неактивный плеер без таймера имитации.
- FAQ: раскрытие мышью и клавишей Enter, скрытые ответы не получают фокус.
- Форма на 390, 768 и 1440 px: подготовка сообщения, выбор пакета из цены, ошибки выбора и неверного контакта, длинное имя, смена канала с восстановлением отдельного черновика, копирование, возврат без потери данных. Доставка менеджеру не выполнялась.
- Privacy/offer на 320 px: заголовки и текст переносятся, ссылки остаются внутри страницы. Юридический текст сохранён.
- Все текущие изображения загрузились после прокрутки; document.fonts.status = loaded. При прохождении сценариев ошибок и предупреждений сайта в консоли не обнаружено.

## Автоматические проверки

- npm ci --ignore-scripts: установлен зафиксированный набор зависимостей (39 пакетов), audit сообщил 0 уязвимостей на дату запуска.
- npm run check: пройден.
- npm test: локальная среда блокирует дочерний процесс ошибкой spawn EPERM. Полный тот же набор запущен через node --test --test-isolation=none tests/*.test.cjs: **19/19 пройдены**.
- Тесты: уникальные ID, локальные ссылки, отсутствие design runtime, lifecycle таймеров, reduced motion, radio-группы, media events, форма, сообщения ошибок, раздельные черновики и fallback буфера.
- Дополнительный аудит: assets существуют, семь исходных PNG совпадают с экспортом по SHA-256; текст main юридических страниц совпадает после нормализации пробелов; git diff --check пройден.

## Производительность и читаемость

Семь PNG (14 328 007 байт) заменены основными WebP (441 494 байта) и отдельными миниатюрами 128 px. Обложки 800×800, иллюстрации подарков 480×360. Рисунок и кадрирование сохранены; исходники остаются в Git-истории и архиве. Изображения ниже hero загружаются лениво, размеры / aspect-ratio заданы до загрузки. Запись полевых Core Web Vitals и измерение на медленном физическом телефоне не выполнялись.

Усилен коралловый CTA: белый на #C9455C — 4,68:1. Основные проверенные пары: белый/сливовый 14,91:1, текст #5C4E70 на розовом 6,19:1, #675A78 на сиреневом 5:1, ошибки 7,67:1. Мелкие акцентные подписи затемнены до #A5304A; крупные коралловые заголовки сохранены. Это выборочная проверка используемых пар, не сертификация всей страницы.

## Что не подтверждено

- Физические iPhone/Android, Safari/Firefox, экранная клавиатура реального телефона, screen reader и загрузка на слабой сети.
- Системное переключение prefers-reduced-motion в реальном браузере: интерфейс управления не предоставляет такую эмуляцию. Логика переключения и отсутствие таймеров проверены автоматически; низкое окно — также визуально.
- Настоящее аудио, серверная доставка, оплата: соответствующих материалов/интеграций в проекте нет.

## Вопросы к владельцу содержимого

1. Подтвердить маркетинговое «10,000+ песен создано», контакт менеджера и актуальность цен. Это данные экспорта, не независимо проверенные факты.
2. «Правки — бесплатно» на лендинге шире формулировки оферты: бесплатно исправляются расхождения с согласованным заданием, существенная смена задания обсуждается отдельно. Условия не изменены.
3. В форме «Песня + видеоклип — от 3 990 ₽», а раздел цен/оферта описывают видеоклип как дополнительный продукт. Уточнить, включена ли базовая песня в 3 990 ₽.
4. Юридические тексты называют адреса https://vivobit.ru/privacy и /offer; в репозитории пока статические privacy.html / offer.html. Ссылки ведут на существующие локальные файлы, но владелец должен подтвердить канонический домен при публикации.

Нужны аудио для историй «Дом, где тебя ждут», «Наше воскресенье», «Наш класс», «До утра», «Папина пластинка». Добавить разрешённые файлы или URL в audioSrc. Прямой backend нужен только при решении заменить текущую ручную передачу заявки.
