# Вивобит — персональные песни

Статический лендинг на HTML/CSS/JavaScript. Продолжение репозитория Violetta:
hero перенесён ранее, остальные разделы восстановлены из пользовательского
экспорта `Hero section with clouds.zip`. В более полном экспорте бренд уже
называется «Вивобит»; именно это название используется на всех страницах.

## Запуск

Сборка и npm для просмотра не нужны:

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. Можно открыть `index.html` непосредственно;
если браузер запрещает копирование в буфер из локального файла, форма выделит
текст заявки для ручного копирования.

## Что есть

- Hero: исходные облака, звёзды и смена пар фраз, один экран в обычном потоке.
- Фиксированная навигация и мобильное меню.
- Четыре шага создания песни из исходного макета.
- Пять историй с обложками и доступным переключением с клавиатуры.
- Цены и дополнительные продукты; CTA выбирает пакет в форме.
- FAQ на native `details` — ответы доступны без JavaScript.
- Форма с получателем, поводом, пакетом и способом связи.
- Футер, `privacy.html` и `offer.html` с текстом из экспорта.

## Заявки

Сервер или CRM в экспорт не включены. Текущий рабочий сценарий:

1. Посетитель заполняет форму и нажимает «Подготовить заявку».
2. Сайт подготавливает сообщение, которое можно проверить и исправить.
3. Посетитель копирует текст и самостоятельно отправляет его менеджеру
   через ссылку `https://t.me/vivo_support`, взятую из исходного футера.

Сайт **не сообщает, что заявка доставлена**. Личные данные не сохраняются
в localStorage, не отправляются скрыто и не добавляются в URL. При недоступном
буфере обмена текст выделяется для ручного копирования. Без JS доступна
прямая ссылка на менеджера, а кнопка подготовки заблокирована.

Автоматический приём заявок и оплата остаются отдельной интеграцией:
нужны согласованный получатель/CRM, серверная валидация и реальные ответы
об успешной отправке или ошибке. Токены ботов/CRM нельзя помещать в frontend.

## Аудио

В экспорте только иллюстрации обложек; MP3/WAV и URL аудио отсутствуют.
По запросу владельца без audioSrc включён визуальный frontend-прототип:
play/pause, перемотка и прогресс без звука и без сетевых запросов к аудио.
prototypeDuration задаёт условную длительность макета, не длительность записи.

Чтобы подключить готовые записи, добавьте файлы и заполните `audioSrc`
для каждой истории в `assets/js/site-data.js`. Воспроизведение, время,
перемотка и ошибки уже связаны с настоящим `HTMLAudioElement`. При выборе
истории с источником используется реальное аудио и его длительность.
Нажатие на основную обложку включает паузу/воспроизведение. Нажатие на
миниатюру выбирает и запускает запись; повторное нажатие переключает паузу.
Стрелки в списке выбирают историю без автоматического запуска. Используется
один audio-элемент с preload="none", без autoplay. Прототип приостанавливается
при уходе со страницы или скрытии вкладки. Блок шага 04 — иллюстрация результата.

## Структура

```text
index.html                         полный лендинг
privacy.html / offer.html          документы из экспорта
assets/css/*.css                   подключаются строго по порядку, см. ниже
assets/js/hero.js                  жизненный цикл и движение hero
assets/js/site-data.js             истории и варианты формы
assets/js/request-core.js          нормализация, валидация, текст заявки
assets/js/landing.js               взаимодействия лендинга
assets/img/                        исходные иллюстрации и обложки (WebP)
tests/                             тесты логики и DOM
docs/PROJECT_STATE.md              состояние и оставшиеся задачи
```

Порядок подключения CSS важен: каждый следующий файл переопределяет предыдущие.

```text
1. hero.css                   существующая сцена hero
2. sections.css               навигация, controls, responsive, новые токены
   └ design-interactions.css  hover/focus/active из экспорта — подключается
                              через @import в первой строке sections.css,
                              то есть каскадом идёт ПЕРЕД её правилами
3. restoration.css            выразительный Hero и фирменный масштаб
4. refinement.css             компактные карточки и редакционная иерархия
5. round-two.css              обложки, цена, компактная форма, облака
6. final-pass.css             финальные правки композиции
7. vinyl-polish.css           винил и переходы в «Примерах»
```

`privacy.html` и `offer.html` подключают только `sections.css` и
`restoration.css` (и вместе с ними `design-interactions.css`).

Это накопленные слои правок, а не тематическое разделение. Консолидация
осознанно не выполнялась — см. «Техдолг» в `docs/PROJECT_STATE.md`.

Статичная разметка разделов сохраняет авторские inline-стили из экспорта,
чтобы перенос не менял композицию. Новые интерактивные состояния вынесены
в именованные классы. `support.js` и служебный runtime Claude Design
на сайте не используются. Иллюстрации сохранены без перерисовки; для сайта подготовлены WebP и отдельные миниатюры. Исходные PNG остаются в архиве дизайна и истории Git.

## Motion и доступность

Сохранены 46 детерминированных звёзд, три облака, два закатных слоя,
цикл смысловой пары 3400 мс и переход 440 мс. Ручная пауза останавливает фон
и слово. Системное `prefers-reduced-motion` включает статичную сцену.
При высоте окна ≤650 px контент находится в обычном потоке документа.
В скрытой вкладке и после исчезновения контента таймеры останавливаются.
Прокрутка не скрывает содержимое Hero; таймеры приостанавливаются после ухода секции за экран. Доступное имя H1 стабильно.

## Проверки

Node.js 22+ и npm нужны только для разработки. `jsdom` — dev dependency,
не часть сайта и не браузерный движок.

```bash
npm ci --ignore-scripts
npm run check
npm test
```

31 тест проверяет motion, навигацию, выбор пакета, вкладки песен,
события настоящего media API через моки, форму и внутренние ссылки.
Браузерная проверка: 12 сентября — встроенный браузер Codex; 23 сентября — Chromium через Playwright на шести размерах. Размеры, сценарии, скриншоты и ограничения описаны в `docs/RELEASE_QA.md`. Реальные устройства, Safari/Firefox, звук и доставка сообщений не проверялись.

Если среда запрещает запуск дочерних процессов (`spawn EPERM`), те же тесты можно запустить командой `node --test --test-isolation=none tests/*.test.cjs`. Это не заменяет браузерную проверку.

## Адаптивная версия

Hero занимает примерно один экран (min-height: 100svh) в обычном потоке. Дополнительного spacer и закрепления сцены нет. На низких окнах контент может естественно увеличить высоту секции. Облака на телефоне не перекрывают заголовок. Меню имеет непрозрачную подложку, Escape возвращает фокус, якоря учитывают шапку.

Форма показывает связанную с полем ошибку и сохраняет ввод при возврате. Контакты Telegram, ВКонтакте и Авито имеют отдельные черновики в памяти страницы; обновление страницы их очищает. Данные не записываются в хранилище браузера.

Документы из формы и футера открываются в новой вкладке (`target="_blank" rel="noopener"`), поэтому заполненная заявка не выгружается вместе со страницей. Ссылки относительные и работают при размещении в подкаталоге. Модального просмотра нет. Черновик нигде не сохраняется: перезагрузка самой страницы его очищает — это осознанное решение не хранить контакты, и именно поэтому документы не должны уводить со страницы. У поля контакта стоит `autocomplete="off"`, так что браузер не восстановит его и при возврате назад. Для Авито контакт не требуется: посетитель копирует подготовленную заявку и сам отправляет её продавцу. Адрес продавца задаётся в assets/js/site-data.js, поле avitoUrl. Telegram и ВКонтакте имеют отдельные подсказки и проверку контакта.

Единая сетка использует контейнер до 1240 px, общие переменные отступов и адаптивную сетку без глобального уменьшения типографики. FAQ изначально закрыт; ответы раскрываются нажатием или клавиатурой.
